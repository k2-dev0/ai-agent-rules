# サブエージェント

- 通常の直列作業はメインが行い、[モデル選択](MODEL_SELECTION.md)で切り替える。子を使うのは独立した並列作業、広い読み取りの文脈隔離、独立レビューが必要な場合だけ。モデルの使い分けだけを目的に委任しない。
- 並列実装は`implementer`、ネスト候補抽出は`nesting-reviewer`の専用定義を使う。その他の調査・レビューは利用可能な読み取り用agentを使い、編集を依頼しない。
- 並列実装は変更pathが互いに重ならず、契約・依存が確定した範囲だけを渡す。メインも実行中の子の対象pathを変更しない。子にGit操作を任せず、全編集の完了後にメインが統合検証・commitする。
- 目的・対象path・完了条件・必要な事実だけをbriefへ渡す。会話全体を継承せず、コード・規約は正本を参照させる。追加委任は禁止。
- 子の結果は変更path・要点・検証結果・未解決事項だけ受け取る。全文ログ・中間出力を再取得しない。
- 待機中は独立した必要作業を進める。作業がなければ完了通知または60秒以上の待機を使う（tool・上位指示の上限まで）。複数の待機先を扱えるtoolではまとめ、返却cursorがあれば次回へ渡す。
- 即時snapshotは初回確認か新しい事実の確認に限る。進展なしの短周期poll、同じ結果の再読、催促、待機だけのモデル交代は禁止。完了を受けたら元の作業を続ける。
