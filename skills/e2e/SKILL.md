## mode

引数は`save`と`run`だけを受け付ける。

- 引数なし: 情報収集、計画承認、保存、実行、報告を行う
- `save`: 情報収集と計画承認後、`@.[agent_name]/e2e/.e2e.md`へ保存して終了する
- `run`: 保存済み計画を読み、再質問せず実行する

## 情報収集

引数なしまたは`save`では、次を一度に一つ質問する。回答済みまたは不要と判断できる質問は繰り返さない。

1. テスト対象のURL、ページ名、component名。複数可。ログインページがあればそのURLも受け取る
2. ログインが必要な場合だけIDとpassword
3. 前提条件。未指定ならページと実装から推測する
4. 完了条件。未指定なら利用者に見える結果とerror経路から推測する

ページ名やcomponent名はコードベースからURLを逆引きする。推測した前提・完了条件はまとめて提示し、修正を受けて確定する。

## 計画と保存

対象URL、マスクしたログイン情報、前提条件、完了条件、順序付きシナリオを一つの計画として提示し、ユーザー承認を得る。承認前にブラウザ操作を始めない。

承認後、一時領域へ計画ドラフトを書き、次の固定経路で保護領域へ反映する。`.[agent_name]/e2e/.e2e.md`を直接編集しない。

```bash
bash [skills_root]/e2e/apply-e2e-plan.sh <ドラフトのパス>
```

Claude Codeはsandbox除外、Codexは`.codex/rules/default.rules`の限定allowを使う。`save`は反映後に終了し、それ以外は実行へ進む。

## 実行

chrome-devtools-mcpで承認済みシナリオを順番に実行する。ログインが必要ならログイン成功後に対象へ進む。

- 各操作後にscreenshotを取得する
- 予期しないerrorや表示崩れは発生時点の状態と再現手順を記録する
- 各シナリオの期待結果と全体の完了条件を別々に判定する
- データ削除などの破壊的操作は直前に確認する
- 外部serviceや本番dataへ影響する操作は警告し、継続判断をユーザーへ求める

## 報告

全体結果を`合格`、`不合格`、`一部不合格`で示し、シナリオごとに結果と備考を表で返す。不合格には問題、再現手順、該当screenshotを付ける。

passwordをログ、comment、計画ファイルへ平文保存しない。認証情報はセッション内だけで使う。一時screenshotを片付け、テスト終了後にbrowserを閉じる。
