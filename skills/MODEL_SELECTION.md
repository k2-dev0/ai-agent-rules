# メインエージェントのモデル選択

この文書がSol／Astraの選択基準の正本である。対象は `switch_main_model` を利用できるCodexのメインエージェントだけ。非対応環境・子エージェントは適用しない。

## 役割

| 担当 | 責務 |
| --- | --- |
| 配布設定 | この文書に選択基準と切り替えタイミングを集約する。各workflowへ同じ基準を複製しない |
| メインエージェント | 元の依頼と残作業を把握し、基準を適用して必要なときだけ切り替える。Sol／Astraのどちらでも親としての調査・設計・レビューの責務は同じ |
| ルーター | 指定されたモデルへの変更と、同じタスクでの自動続行を実行する。作業内容の分類や変更理由の審査はしない |
| implementer等の子エージェント | 呼び出し元workflowと専用定義の担当範囲を守る。親のモデル選択を引き受けず、自分のモデルも変更しない |

モデル選択によってworkflowを自動起動したり、実装の担当範囲を変更したりしない。初回実装を専用implementerへ委任するかは、既存のworkflowに従う。

## 選び方

ユーザーがモデルを明示した場合は通常の指示優先順位で扱う。それ以外は、次に自分が担当する残作業に基準を適用する。Astraを必要とする条件がなければSolを選ぶ。判断材料が不足するときは、現在のモデルで必要な範囲を確認する。

| Sol（gpt-5.6-sol） | Astra（gpt-6-astra） |
| --- | --- |
| 仕様・変更範囲・確認方法が明確で、既存パターンに沿って進められる | 責務・仕様の矛盾・影響範囲そのものを調査し組み立てる必要がある |
| 局所的な説明、修正、既存機能の展開、機械的変更 | 複数の状態・領域をまたぐ整合性、並行実行、保存・再処理などの難しい設計 |
| 誤りを既存の検証で捕まえやすい | 見落としの影響が大きく、既存の検証では重要な誤りが残りうる |

ファイル数、ツール回数、経過時間だけでAstraへ変えない。環境不備や承認待ちも、それだけでは切り替え理由にならない。Astraが必要な判断を終え、残りが明確な定型作業になったらSolへ戻す。基準に従って選んだモデルが現在のモデルと同じなら、切り替えを呼ばない。

## 見直すタイミング

| 区切り | 判断 |
| --- | --- |
| 新しい依頼を受けたとき | 依頼と既存の文脈から残作業を判断する。Astraが必要だと既に分かる場合は、難所へ着手する前に切り替える |
| 初期調査で作業内容が分かったとき | 既存パターンで進められるか、仕様の矛盾・複数経路の整合性・難しい設計判断があるかを見直す |
| 新しい事実で前提が崩れたとき | 原因仮説、変更範囲、受け入れ条件の組み直しが必要なら、修正へ進む前に見直す。単なるテスト失敗だけでは切り替えない |
| 実装結果を受け取り、レビューへ進むとき | 変更漏れ、状態間の整合性、検証の穴など、レビューで必要な判断に合わせる。レビューという工程名だけでAstraにしない |
| 難しい判断とその確認を終えたとき | 残りが定型作業ならSolへ戻す。設計が確定しても難しい統合レビューが残る場合は、その残作業まで考慮する |

これはモデル選択を見直す区切りであり、区切りごとの交代を義務にしない。`meeting`、`tdd`、`errand`、`polish`などの名前だけでモデルを固定しない。

「続けて」「そこを直して」や作業途中の質問では、元の依頼と未完了の判断を保持する。短い入力だからSolへ戻すとは判断しない。実装・テストの待機だけを理由にSolへ下げ、直後の難しいレビューでAstraへ戻す往復は行わない。短い完了報告だけが残る場合も、そのためだけの交代は不要。

## 切り替えと続行

現在のタスクに登録された専用ツール `switch_main_model` を直接呼ぶ。以下はツール呼び出しの例であり、シェルコマンドではない。選択した切り替え先の一方だけを呼ぶ。

| 切り替え先 | ツール呼び出し |
| --- | --- |
| Sol | `switch_main_model({"model":"gpt-5.6-sol"})` |
| Astra | `switch_main_model({"model":"gpt-6-astra"})` |

切り替え用の実行ファイルやコマンドをリポジトリから探さない。ツールが登録されていなければ、現在のモデルで元の依頼を続ける。

- 自分で判断して切り替え先のモデル名だけを渡す。理由・評価票の提出も、モデル選択用の子エージェントも不要。
- 他のツールと並列に呼ばず、実行中ツールと承認待ちを終えてから単独で呼ぶ。進行中のコマンド、待機中のコード実行、実行中の子エージェントが残っている間は呼ばない。切り替えるために、それらを打ち切らない。
- 成功するとルーターが現在の実行区間を終了し、新モデルで同じタスクを自動続行する。切り替えに伴う中断はユーザーの停止指示ではない。新モデルは元の依頼の残作業を続け、完了済みの操作や切り替えをやり直さない。
- 切り替え直後は、引き継いだ判断に沿って予定していた残作業へ進む。新しい事実や作業内容の変化がないまま、開始時の選択をやり直して元のモデルへ戻さない。
- ユーザーに追加入力、別タスク、ターミナル操作、アプリ再起動を求めない。ユーザー自身が停止した場合は、その指示を優先する。
- 失敗を成功扱いしない。実行中処理が理由なら完了を待つ。同じ拒否を条件が変わらないまま繰り返さない。利用不能や権限上の制約を、モデル名の偽装、審査の無効化、設定の書き換えで回避しない。
- 思考量はSol／Astraともhighを基準とする。独立した自動最適化はしない。
- メインの交代で役割・workflowを変更しない。implementerのLuna／max、権限、承認、作業ディレクトリ、既存のツールと指示を維持する。設定ファイルやagent定義を切り替えのたびに書き換えない。
