# メインエージェントのモデル選択

この文書がSol／Astraの選択基準の正本である。対象は `switch_main_model` を利用できるCodexのメインエージェントだけ。非対応環境・子エージェントは適用しない。

## 選び方

ユーザーがモデルを明示した場合は通常の指示優先順位で扱う。それ以外は、作業開始時と作業の性質が変わった時点で次の基準を適用する。

| Sol（gpt-5.6-sol） | Astra（gpt-6-astra） |
| --- | --- |
| 仕様・変更範囲・確認方法が明確で、既存パターンに沿って進められる | 責務・仕様の矛盾・影響範囲そのものを調査し組み立てる必要がある |
| 局所的な説明、修正、既存機能の展開、機械的変更 | 複数の状態・領域をまたぐ整合性、並行実行、保存・再処理などの難しい設計 |
| 誤りを既存の検証で捕まえやすい | 見落としの影響が大きく、既存の検証では重要な誤りが残りうる |

ファイル数、ツール回数、経過時間だけでAstraへ変えない。環境不備や承認待ちも、それだけでは切り替え理由にならない。Astraが必要な判断を終え、残りが明確な定型作業になったらSolへ戻す。現在のモデルで条件を満たす場合は変更しない。

## 切り替えと続行

- 自分で判断して `switch_main_model` に切り替え先のモデル名を渡す。理由・評価票の提出も、モデル選択用の子エージェントも不要。
- 他のツールと並列に呼ばず、実行中ツールと承認待ちを終えてから単独で呼ぶ。進行中のコマンドや待機中のコード実行が残っている間は呼ばない。
- 成功するとルーターが現在の実行区間を終了し、新モデルで同じタスクを自動続行する。切り替えに伴う中断はユーザーの停止指示ではない。新モデルは元の依頼の残作業を続け、完了済みの操作や切り替えをやり直さない。
- ユーザーに追加入力、別タスク、ターミナル操作、アプリ再起動を求めない。ユーザー自身が停止した場合は、その指示を優先する。
- 失敗を成功扱いしない。利用不能や権限上の制約を、モデル名の偽装、審査の無効化、設定の書き換えで回避しない。
- 思考量はSol／Astraともhighを基準とする。独立した自動最適化はしない。
- メインの交代で役割・workflowを変更しない。implementerのLuna／max、権限、承認、作業ディレクトリ、既存のツールと指示を維持する。設定ファイルやagent定義を切り替えのたびに書き換えない。
