# メインモデルの選択

ユーザーの明示指定を優先し、それ以外は残作業に必要な判断で選ぶ。

| モデル | effort | 選ぶ条件 |
| --- | --- | --- |
| Luna（`gpt-5.6-luna`） | max | 新しい仕様判断が不要で、既存コード・確定済み方針から変更先、不変条件、検証方法を決定できる作業。削除、rename、移動、参照追従、既存実装への置換、複数ファイルの同型修正 |
| Sol（`gpt-5.6-sol`） | high | 複数の妥当な方針があり、公開API、互換性、責務境界、データ契約、エラー契約、UIの表示・操作・状態遷移について新しい選択が必要な作業 |
| Astra（`gpt-6-astra`） | high | 仕様・責務・影響範囲の組み直し、並行実行・保存・再処理などの複雑な整合性判断、既存の検証では重大な見落としが残る作業 |

## 見直すタイミング

依頼開始時と初期調査直後かつ実装開始前に、残作業を必ず再判定する。前提の変化、レビュー着手前、難所の解消後にも見直す。ユーザーの訂正や調査結果によって仕様解釈が崩れた場合は、修正に着手する前に再判定する。

未解決の判断が上位モデルの条件に該当したら、その判断に依存する編集を止め、「切り替え」に従って交代する。訂正・API変更・UI変更という事実だけでは昇格しない。ユーザーしか決められない要件は必要な点だけ確認する。

採用方針、不変条件、変更範囲、検証方法が確定したら、残作業を表に照らして再判定する。

工程名、ファイル数、検索量、経過時間、単なるテスト失敗・環境不備では決めない。上位モデルを維持するのは、残作業が表の上位モデルの選択条件に該当する場合だけ。短い追加入力でも元の依頼を保持し、待機や短い完了報告だけのために交代しない。

## 切り替え

- モデルまたは設定が現在と異なる場合だけ、専用ツール `switch_model({"model":"モデルID","config":{"effort":"思考量"}})` を直接呼ぶ。`config.effort`は必須。例：`switch_model({"model":"gpt-6-astra","config":{"effort":"high"}})`。追加設定も`config`内に指定する。同じモデルの設定変更も可。コマンド探索・変更理由の提出は不要。
- 先行するツール・コマンド・子エージェント・承認の結果をすべて受け取る。次の応答では`switch_model`だけを呼び、他のツール呼び出しを含めない。切り替えのために処理を打ち切らない。
- batonの受付結果`pending`は適用成功ではない。追加作業を始めず引き継ぎを待つ。続行先で`status: "applied"`のモデル・設定を確認して、同じタスクの残作業を再開する。`baton`による中断をユーザーの停止と扱わない。完了済み操作を繰り返さず、新しい事実なしに元のモデルへ戻さない。判断の確定により残作業が下位モデルの条件を満たした場合は、新しい事実として扱う。ユーザーの停止指示は優先する。
- 受付前の拒否は`result.success: false`、理由は`result.contentItems[].text`。モデル・設定・実行区間は維持される。固定エラー文言で判定しない。
- 中断後の続行失敗はクライアントへ`error`通知され、設定だけ変更済みの場合がある。再開時は実際のモデル・設定を確認し、不明なら依存する変更を止めて報告する。変更前の状態を前提に続行・再試行しない。
- 実行中のツール・子エージェントまたは承認待ちを理由に拒否された場合は、その完了結果を受け取った次の応答で`switch_model`だけを1回呼び直す。切り替え前に後続作業を続けない。
- effortはユーザー指定、なければ表の値を渡す。交代によって役割・workflow・子エージェント定義・権限を変えない。

## 切り替え不能時

専用ツールが未提供、選定モデル・effortが利用不能、または再試行で解消しない拒否・失敗の場合は次に従う。設定ファイルの変更を、現在のタスクの切り替え成功として扱わない。

- ユーザーの明示指定を満たせない：切り替え不能を報告し、指定と異なるモデル・effortで対象作業を続けない。
- 下位モデルへの降格ができない：選定したモデル・effortと切り替え不能を短く報告し、現在のモデルで続行する。同じ利用不能条件では再試行・再報告を繰り返さない。
- 必要な昇格ができない：その判断に依存する変更を止め、選定したモデル・effortと切り替え不能を報告する。依存しない調査・検証は続行できる。
- 同一モデルのeffort変更ができない：引き上げは必要な昇格、引き下げは降格と同じ扱いにする。
