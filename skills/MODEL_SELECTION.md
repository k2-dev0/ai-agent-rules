# メインモデルの選択

ユーザーの明示指定を優先し、それ以外は残作業に必要な判断で選ぶ。

| モデル | effort | 選ぶ条件 |
| --- | --- | --- |
| Luna（`gpt-5.6-luna`） | max | 新しい仕様判断が不要で、既存コード・確定済み方針から変更先、不変条件、検証方法を決定できる作業。削除、rename、移動、参照追従、既存実装への置換、複数ファイルの同型修正 |
| Sol（`gpt-5.6-sol`） | high | 複数の妥当な方針があり、公開API、互換性、責務境界、データ契約、エラー契約について新しい選択が必要な作業 |
| Astra（`gpt-6-astra`） | high | 仕様・責務・影響範囲の組み直し、並行実行・保存・再処理などの複雑な整合性判断、既存の検証では重大な見落としが残る作業 |

## 見直すタイミング

依頼開始時と初期調査直後かつ実装開始前に、残作業を必ず再判定する。前提の変化、レビュー着手前、難所の解消後にも見直す。

工程名、ファイル数、検索量、経過時間、単なるテスト失敗・環境不備では決めない。上位モデルを維持するのは未解決の設計判断を特定できる場合だけ。短い追加入力でも元の依頼を保持し、待機や短い完了報告だけのために交代しない。

## 切り替え

- モデルまたは設定が現在と異なる場合だけ、専用ツール `switch_model({"model":"モデルID","config":{"effort":"思考量"}})` を直接呼ぶ。`config.effort`は必須。例：`switch_model({"model":"gpt-6-astra","config":{"effort":"high"}})`。追加設定も`config`内に指定する。同じモデルの設定変更も可。コマンド探索・変更理由の提出は不要。
- 先行するツール・コマンド・子エージェント・承認の結果をすべて受け取る。次の応答では`switch_model`だけを呼び、他のツール呼び出しを含めない。切り替えのために処理を打ち切らない。
- 成功時は元の実行区間が終了し、続行先が`switch_model`の`status: "applied"`を受け取る。`baton`による中断なので、同じタスクの残作業を再開する。完了済み操作を繰り返さず、新しい事実なしに元のモデルへ戻さない。ユーザーの停止指示は優先する。
- 中断前の拒否は`result.success: false`で、理由は`result.contentItems[].text`。モデル・設定・実行区間は維持される。固定エラー文言で判定しない。
- 実行中のツール・子エージェントまたは承認待ちを理由に拒否された場合は、その完了結果を受け取った次の応答で`switch_model`だけを1回呼び直す。切り替え前に後続作業を続けない。
- effortはユーザー指定、なければ表の値を渡す。交代によって役割・workflow・子エージェント定義・権限を変えない。
