# メインモデルの切り替え

`MODEL_SELECTION.md`の選定値が現在のモデル・effortと異なる場合だけ読む。

## 手順

- モデルまたは設定が現在と異なる場合だけ、専用ツール `switch_model({"model":"モデルID","config":{"effort":"思考量"}})` を直接呼ぶ
  - `config.effort`は必須
  - 例：`switch_model({"model":"gpt-6-astra","config":{"effort":"high"}})`
  - 追加設定も`config`内に指定する
  - 同じモデルの設定変更も可
  - コマンド探索・変更理由の提出は不要
- 先行するツール・コマンド・子エージェント・承認の結果をすべて受け取る
  - 次の応答では`switch_model`だけを呼び、他のツール呼び出しを含めない
  - 切り替えのために処理を打ち切らない
  - 実装方針と難易度評価の最終結果を引き継ぐ
- 切替要求の記録、受付結果`pending`、空のツール返答、要求内容の再掲だけでは適用成功とみなさない
  - 追加作業を始めず引き継ぎを待つ
  - 続行先で`status: "applied"`と、実際のモデル・effortが選定値に一致することを確認してから、同じタスクの残作業を再開する
  - 一つでも確認できない場合は編集を開始せず、「切り替え不能時」に従って報告する
  - `baton`による中断をユーザーの停止と扱わない
  - 完了済み操作を繰り返さず、方針確定・工程移行だけで元のモデルへ戻さない
  - 再選定は`MODEL_SELECTION.md`の再評価条件に従う
  - 修正後レビューで同じfile内の関数・section・testへの指摘が再発した場合は一段上へ昇格し、Astra / highでは維持する
  - ユーザーの停止指示は優先する
- 受付前の拒否は`result.success: false`、理由は`result.contentItems[].text`
  - モデル・設定・実行区間は維持される
  - 固定エラー文言で判定しない
- 中断後の続行失敗はクライアントへ`error`通知され、設定だけ変更済みの場合がある
  - 再開時は実際のモデル・設定を確認し、不明なら依存する変更を止めて報告する
  - 変更前の状態を前提に続行・再試行しない
- 実行中のツール・子エージェントまたは承認待ちを理由に拒否された場合は、その完了結果を受け取った次の応答で`switch_model`だけを1回呼び直す
  - 切り替え前に後続作業を続けない
- effortはユーザー指定、なければ`MODEL_SELECTION.md`の選定値を渡す
  - 交代によって役割・workflow・子エージェント定義・権限を変えない

## 切り替え不能時

専用ツールが未提供、選定モデル・effortが利用不能、または再試行で解消しない拒否・失敗の場合は次に従う。設定ファイルの変更を、現在のタスクの切り替え成功として扱わない。

- ユーザーの明示指定を満たせない：切り替え不能を報告し、指定と異なるモデル・effortで対象作業を続けない
- 下位モデルへの降格ができない：選定したモデル・effortと切り替え不能を短く報告し、現在のモデルで続行する
  - 同じ利用不能条件では再試行・再報告を繰り返さない
- 必要な昇格ができない：その判断に依存する変更を止め、選定したモデル・effortと切り替え不能を報告する
  - 依存しない調査・検証は続行できる
- 同一モデルのeffort変更ができない：引き上げは必要な昇格、引き下げは降格と同じ扱いにする
